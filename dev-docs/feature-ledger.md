## 1. 怎么用这份账本

1. **开工前先读三栏：** 必须 / 不需要 / 可以有。不在账本里的功能，默认先不写代码。
2. **改账本才能改方向。** 要把某项从「可以有」升成「必须」，或把「必须」降成「不做」，改本文件并写一行变更记录。
3. **状态只改「叶读」列。** `已有` / `部分` / `缺口` / `不做`。不要为了好看去发明功能。
4. **个人阅读器，不是平台。** 微信读书赢在书和人；叶读赢在纸感、打开速度、以及「人能读、AI 也能读」的书库。
5. **完成前过三问。** 见下一节。没过关不得把状态改成 `已有`。

判定口诀：

- **必须：** 没有它就不成其为阅读器，或没有它就不成其为叶读。
- **不需要：** 成熟阅读器有，但和叶读身份冲突，或会把项目拖成 Readest。
- **可以有：** 有则更好，没有也能每天用；排在必须项之后。

### 1.1 完成关（每项必过）

每做完一项功能，**先反问，再交差**。三问都要有具体答案，不能用「应该没问题」带过。过不了就改实现，不要加功能来补。

| 问 | 过关标准 | 常见翻车 |
| --- | --- | --- |
| **是不是最佳实践？** | 先查成熟阅读器和开源实现（微信读书 / Apple Books / Kindle / Foliate / foliate-js）。有现成、许可证干净的做法就用；不要自造分页、自造 CFI、自造 EPUB 解析。 | 发明一套和业界不同的进度格式；为了「更智能」上向量库 |
| **是不是和需求最匹配？** | 对照账本该行的 ID 和说明，只解决那一行。叶读身份（纸感、对照、AI 书库、本地）优先于「别人有所以我也有」。 | 做书内搜索时顺手做了全文 AI 问答；做书签时做成了阅读统计 |
| **是不是最小代码？** | 能用现有模块就扩展，不新开子系统。文件仍尽量短。没有第二调用方就不抽框架。删掉用不上的分支、配置和 UI。 | 一个搜索框配三层抽象；为 NAS 先写微服务网关 |

写法（交差时附在实现说明里，三行即可）：

```text
实践：……（对过哪家 / 哪份既有代码）
匹配：只覆盖 Mx / Cx ……，没有做 ……
最小：改了哪些文件；为什么不必再多一层
```

## 2. Lumi 是什么

Lumi（Luminary）是一台 **macOS 优先** 的私人阅读器。名字来自拉丁语 lumen：把还没索引的书当成沉睡的文本，建好知识库之后整本被点亮。

- 书在自己手里（本地，可放到飞牛 NAS 卷上）。
- 中文像纸书，英文像一篇排过版的文章。
- 对照翻译是阅读的一部分，不是外挂网页。
- 每本书生成一份 **AI 可检索的书库**，人和模型用同一份文本。

Lumi 不是：书店、社交网络、听书 App、Calibre、PDF 工作站、Readest 的精简版。

许可边界：内核 foliate-js（MIT）。**禁止**抄 Readest 源码（AGPL）。

| X15 | 默认全书 AI 摘要、自动写读后感 | AI 书库给模型原文和骨架；摘要是人问出来的，不在导入时烧配额 |

## 7. 叶读已有（2026-09-17 快照）

用来对照缺口，避免把已做的再做一遍。

- 书架：封面、导入、删除、续读、试读本
- 阅读：分页/滚动、滚轮跨章、键盘、无铬点击、目录
- 纸感：十种纸色；中文缩进；英文重排 + Newsreader + 素页
- 字体：思源宋/黑、仿宋、楷、圆、苹方、Palatino、Newsreader
- 进度：全书条、可拖、低饱和虹彩
- 划线六色、想法、笔记侧栏、CFI、书签
- 书内全文搜索
- 对照：Google gtx、章级预译、选区「译此段」
- AI 书库：导入生成 `INDEX.md` + 每书 `AI.md` / `digest.md` / `chapters/` / `chunks.jsonl`
- 壳：Tauri v2 工程；Docker 文件；开发态 Vite 写入 `~/.leaf-reader/library`

已知限制（账本承认、不假装没有）：

- 书本体仍在 IndexedDB，跨设备 UI 不共享文件
- CSS columns 对宽表、预分页 EPUB 不友好
- Docker 镜像未在本机 daemon 打过
- 对照依赖网络；微软免费接口不稳，回落谷歌

## 8. 周期

不写日历。只写依赖。当前周期停在「必须项做完」，不要并行铺开可以有。

```text
周期 A  阅读器补全     M8 搜索 → M9 书签 → M1 坏书提示
周期 B  落盘与壳       M10 书文件落盘 → M12 拖入/关联
周期 C  NAS 跑通       M24 飞牛卷 + AI 书库一致
周期 D  纸感加固       真书回归 M20–M22、M7
周期 E  可以有         从 C1 起，一次一项
```

任何「做个 AI 聊天窗读这本书」的请求：先用已有 AI 书库（M23），不要在阅读页再嵌一套 RAG 运行时，除非账本新增必须项。
