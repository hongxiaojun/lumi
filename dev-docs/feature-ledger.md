## 1. 怎么用这份账本

1. **开工前先读三栏：** 必须 / 不需要 / 可以有。不在账本里的功能，默认先不写代码。
2. **改账本才能改方向。** 要把某项从「可以有」升成「必须」，或把「必须」降成「不做」，改本文件并写一行变更记录。
3. **状态只改「叶读」列。** `已有` / `部分` / `缺口` / `不做`。不要为了好看去发明功能。
4. **个人阅读器，不是平台。** 微信读书赢在书和人；叶读赢在纸感、打开速度、以及「人能读、AI 也能读」的书库。
5. **完成前过三问。** 见下一节。没过关不得把状态改成 `已有`。

判定口诀：

- **必须：** 没有它就不成其为阅读器，或没有它就不成其为叶读。
- **不需要：** 成熟阅读器有，但和叶读身份冲突，或会把项目拖成 Readest。
- **可以有：** 有则更好，没有也能每天用；排在必须项之后。

### 1.1 完成关（每项必过）

每做完一项功能，**先反问，再交差**。三问都要有具体答案，不能用「应该没问题」带过。过不了就改实现，不要加功能来补。

| 问              | 过关标准                                                                                                      | 常见翻车                           |
| -------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------ |
| **是不是最佳实践？**   | 先查成熟阅读器和开源实现（微信读书 / Apple Books / Kindle / Foliate / foliate-js）。有现成、许可证干净的做法就用；不要自造分页、自造 CFI、自造 EPUB 解析。 | 发明一套和业界不同的进度格式；为了「更智能」上向量库     |
| **是不是和需求最匹配？** | 对照账本该行的 ID 和说明，只解决那一行。叶读身份（纸感、对照、AI 书库、本地）优先于「别人有所以我也有」。                                                  | 做书内搜索时顺手做了全文 AI 问答；做书签时做成了阅读统计 |
| **是不是最小代码？**   | 能用现有模块就扩展，不新开子系统。文件仍尽量短。没有第二调用方就不抽框架。删掉用不上的分支、配置和 UI。                                                     | 一个搜索框配三层抽象；为 NAS 先写微服务网关       |

写法（交差时附在实现说明里，三行即可）：

```text
实践：……（对过哪家 / 哪份既有代码）
匹配：只覆盖 Mx / Cx ……，没有做 ……
最小：改了哪些文件；为什么不必再多一层
```

## 2. Lumi 是什么

Lumi（Luminary）是一台 **macOS 优先** 的私人阅读器。名字来自拉丁语 lumen：把还没索引的书当成沉睡的文本，建好知识库之后整本被点亮。

- 书在自己手里（本地，可放到飞牛 NAS 卷上）。
- 中文像纸书，英文像一篇排过版的文章。
- 对照翻译是阅读的一部分，不是外挂网页。
- 每本书生成一份 **AI 可检索的书库**，人和模型用同一份文本。

Lumi 不是：书店、社交网络、听书 App、Calibre、PDF 工作站、Readest 的精简版。

许可边界：内核 foliate-js（MIT）。**禁止**抄 Readest 源码（AGPL）。

### 3.1 BookOrbit（2026-10-29，只看形状）

许可是 AGPL-3.0-only，和 Readest 一样。只记产品形状，不抄源码，不换内核。

它是自托管的多用户书库：网页、iPhone、手表、Kobo、KOReader 共用进度和划线。技术栈是 Vue、NestJS、PostgreSQL。叶读仍是一台 Mac 上的私人阅读器：foliate-js（MIT），IndexedDB，书旁一份 meta.json。

相同的阅读习惯：

- 书文件在磁盘上。清掉网页存储，书架还在。
- EPUB 进度是 CFI 加全书百分比，PDF 是页码。不自造位置格式。
- 划线、书签和书文件分开存。
- 每种书有默认外观，单本可以盖过默认。
- 流式 EPUB 分页或滚动。声明为整页排好的书另走，不套正文排版。

数据上他们这样做。叶读只吸收写进「可以有」的几条：

- 用内容指纹认出同一份文件。改名或再拖一次，仍是原来那本。叶读现在再导入会多一张卡，见 C17。叶读仍是一本书一个文件，不改成一本书一个文件夹。
- 进度按「这一份文件、这个人」记。朗读停在哪一句单独记，续读不把它当成翻到的页。见 C5。
- 划线的中心是原文。位置只是锚，对不上就标出来，不猜。叶读的 CFI 加前后文已经是这条。PDF 先合成 EPUB，不另建多种锚点。
- 设置读入时丢掉超出范围的值。格式有一套默认，单本只存改过的项。叶读已是设备默认加单本外观。
- 续读看最近一次真正翻页。改设置或做同步不算读过。叶读单机用最近打开，够用。做到 C7 时再把这两种时间分开。

不吸收的部分见 X16：深色统计首页、连续阅读横条、在听、目标环、今日金句、丛书管理、智能筛选。叶读保持浅色纸面和现有两种书架。有声书先不做。

他们写明 SMB/NFS 网络盘不能当书库盘。M24 仍做飞牛，卷用容器里的本地路径。

界面里留下的是 C14、C15、C16。选区上的划线、译这一段、从这里读，叶读已有。词典仍是 C1。页脚「还剩多少时间」不单独立项。

### 4.3 必须项的完成顺序

先补阅读器缺口，再把叶读特色从「能用」打到「稳」。

1. M8 书内搜索
2. M9 书签
3. M13 PDF 检测与文字层重排（[pdf-import.md](pdf-import.md) 验证后再写）

6. M12 拖入/文件关联
7. M24 在飞牛上跑通并核对 AI 书库落卷
