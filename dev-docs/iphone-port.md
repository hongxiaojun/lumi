# macOS → iPhone 迁移开发测试手册

这份手册写给 Lumi（`app.leaf.reader`）。它只做自己的 iPhone，用免费 Apple ID 临时签名，不进 App Store。手机是另一座书架，书留在 App 容器里，不和 Mac 的 `~/Library/Application Support/app.leaf.reader` 合并。

来源：Apple Human Interface Guidelines 的 Layout、Designing for iOS、Buttons；Apple TN3187（UIScene）；Tauri 2 的 iOS 开发与签名说明；以及 2026-11-06 这台 iPhone 17 上已经发生过的失败。

以后每次做手机适配，先读「原则」和「一次适配的套路」，再查下面的分层和失败记录。

## 原则

1. 功能平移，几何重排。同一个功能可以留下，但它的主人、位置和点击归属要按手指和窄屏重定。桌面上能叠放，是因为指针小、窗口大、悬停才出现。这三件在手机上都不成立。
2. 两条轴分开判断。排版看可用宽度：窄屏走底栏和单列，宽屏保持原来的侧栏。平台能力看编译目标：菜单栏、文件面板、Vision 这类只有 macOS 才有的能力用 `target_os` 隔开。不用「是不是 iPhone」一个开关同时决定这两件事。
3. 机器、壳、数据、交互四层，一层没过不做下一层。
4. 浮层同时可见时，只有两种合法结果：矩形不相交，或者上面那块完整盖住下面那块并接收点击。交叉、错位、点到被盖住的按钮，都算没完成。
5. 悬停不是一条路径。每个「鼠标移上去才出现」的控件，都要有一条不靠悬停的入口。
6. 手指抬起才改界面，并吃掉随后那一次 click。触点从 touch 坐标读，不把 touch 事件当成坐标是 0 的鼠标。
7. 编译成功和安装成功只证明包出去了。解压嵌入资源、搜到这版的文案，才证明装的是这版。
8. 改之前先列出这一屏的状态。至少包括静止、召唤层打开、模态层打开。有输入框就加键盘打开。阅读页再加划线打开。每一张都要核对交付标准。没走到的状态写成未测，不写成通过。单元测试代替不了这些状态。
9. 一次只改一屏，并留下一句只有这版才有的文案，用来核对嵌入包。
10. 模拟器负责把第 8 条的状态走完。真机负责签名、启动、主屏幕图标，以及模拟器看不了的项。模拟器运行时不存在时，先写明，再决定是装运行时还是把视觉验收留空。留空就不能称为适配完成。

## 一次适配的套路

每次只改一屏。先写状态名单，再改代码。

1. 写下这一屏的状态名单，以及每张状态下可见的浮层。给每块浮层指定主人：舞台、常驻锚点、召唤层、模态层、瞬时层。
2. 标出相交的矩形。先改归属，再改样式。不要先加大 `z-index`。
3. 为新的手势写一条会失败的测试：点、滑动、抬起、坐标。纯样式可以不写测试。
4. 只改窄屏分支。宽屏路径跑原来的测试，确认原来的侧栏、滚轮和悬停还在。
5. 删掉旧的 iOS 嵌入缓存，重新打包。解压后搜这版才有的那句文案。
6. 按状态名单逐张走，每张核对交付标准。模拟器运行时存在时，先在模拟器里走完。真机再看签名、启动、图标和模拟器看不了的项。
7. 交回时分开写：走过的状态、未测的状态、桌面原路径是否还在。只要有一张状态未测，就写「视觉验收未完成」，不写「适配完成」。

这台 Mac 在 2026-11-06 没有安装任何 iPhone 模拟器运行时。当时的安装只证明包能签名并启动，没有走完状态名单。

浮层归属：

| 层 | 主人 | 规则 |
| --- | --- | --- |
| 舞台 | 书页 | 只翻页和滚动，不放按钮 |
| 常驻锚点 | 返回、底栏 | 数量少，固定在安全区内，两两不相交 |
| 召唤层 | 阅读菜单 | 出现时接替常驻锚点的那个角，不另放一个同样的按钮 |
| 模态层 | 阅读设置、我的字体、划线条 | 同时只开一个，盖住下面所有浮层，并接手点击 |
| 瞬时层 | 提示、短句状态 | 不接收点击，不挡常驻锚点 |

交付标准，五条都要满足：

1. 每个可点区域都在安全区内，并且至少 44×44 pt。
2. 常驻按钮和召唤菜单不占用同一个角。
3. 模态层同时只有一个。它打开时，常驻按钮不再露在它外面。
4. 手指按下的那一块，就是抬起时响应的那一块。
5. 舞台上的翻页和滚动，只在没有浮层接住这次触摸时发生。

## 1. 先分清四层

成熟做法不是把 Mac 窗口缩小。四层分开做，一层没过就不要做下一层。

| 层 | 问的问题 | 过门的证据 |
| --- | --- | --- |
| 机器 | 这台电脑能不能给这台手机签名 | `xcodebuild -version` 的 SDK 不低于手机系统；手机在 `devicectl list devices` 里是 paired |
| 壳 | 进程能不能活过启动，页面是不是自己的文件 | 进程还在；屏幕不是黑的；不请求 `localhost:5173` |
| 数据 | 书存在哪，和 Mac 是否隔离 | 手机书只在这个 App 容器里；删掉 Mac 上的书，手机上的还在 |
| 交互 | 手指能不能完成 Mac 上用指针完成的事 | 下面第 6 节的清单，每一项在真机上点过 |

Mac 行为是底线。窄屏分支用宽度判断，不用「是不是 iPhone」这一个开关去改桌面。

## 2. 机器准备

这些是官方要求，也是这台机器上缺一不可的。

1. 用和手机主系统配套的 Xcode。只装 Command Line Tools 不够。旧 Xcode 的 SDK 签不出新手机。这台是 Xcode 27.2，路径 `/Applications/Xcode.app`。
2. `xcode-select` 指向这份 Xcode。`PATH` 里要有 `$HOME/.cargo/bin`，否则会用到 Homebrew 的 rustc。
3. Rust 目标：`aarch64-apple-ios`。模拟器目标只有在模拟器运行时安装之后才有用。
4. CocoaPods 用 Homebrew。`sudo gem install` 在这台机器上失败过。
5. 手机用线连上，点「信任」。免费个人团队第一次没有设备记录，描述文件创建不出来。
6. Xcode 账号里加入这个 Apple ID。签名用 Automatic，`DEVELOPMENT_TEAM` 写在 `bundle.iOS`。
7. 磁盘要留下 Xcode 和一次 release 编译的空间。这台 Data 卷曾只剩约 17 GB，再下一份模拟器运行时就会写满。

免费个人团队的边界，按 Apple 账户说明：

- 描述文件 7 天过期。过期后手机上打不开，要用同一套命令重签再装。
- 不能上架，不能用 TestFlight，不能给第二个人装。
- 推送、iCloud、App Groups、Associated Domains 这类能力不要进这个包。Lumi 的局域网同步是 C7，不靠这些能力。
- 证书和描述文件由 Xcode 管。不要去开发者网站手工做一份。

装上之后，手机要在「设置 → 通用 → VPN 与设备管理」里信任开发者一次。没信任时，安装成功，启动报 Security。

## 3. 壳：让 App 自己带上页面

Tauri 的 `tauri ios dev` 是开发环：手机去连电脑上的 Vite。它要本地网络权限，手机关机或电脑不在就打不开。给自己每天看的包不走这条路。

发布包必须：

1. `tauri` 打开 `custom-protocol`。没开时，`--release` 仍是开发构建，页面地址还是 `devUrl`。
2. `pnpm build` 先写出 `dist`。`frontendDist` 指向它。
3. 用 `cargo rustc --release --target aarch64-apple-ios --lib --crate-type staticlib` 产出静态库。Xcode 只链接 Swift 符号，单独 `cargo build --lib` 会缺 `_log_stdout`、`_on_webview_created`、`_run_plugin_command`。
4. 嵌入资源是 Brotli。确认新界面时，解压 `tauri-codegen-assets` 再搜文案。明文搜不到不等于没嵌进去。
5. `cargo:rerun-if-changed=../dist` 不可靠。改完前端后删掉 `target/aarch64-apple-ios/release/build/leaf-reader-*` 和对应 fingerprint，再编。
6. 二进制里出现 `localhost:5173` 字符串不算失败，配置文本会留在里面。以解压后的页面文案为准。

`tauri ios build` 在没有模拟器运行时时会拒绝。这台机器用 `xcodebuild -destination 'generic/platform=iOS'` 编真机包，再用 `devicectl device install app` 安装。安装时手机要解锁。锁屏时安装可以成功，启动会报 Locked。

生成工程在 `src-tauri/gen/apple`，由 `project.yml` 经 xcodegen 产生。改脚本以 `project.yml` 为准，然后重新生成。不要只改 `project.pbxproj`。

## 4. 壳：iOS 26 以后的场景生命周期

用新 SDK 编译时，没有 `UIApplicationSceneManifest` 会在启动时中断。清单里要有 `UIWindowSceneSessionRoleApplication`，配置名用 `TaoScene`。

不要在清单里写死 `UISceneDelegateClassName`。tao 的场景代理是稍后注册的，写死类名会在类还不存在时崩溃。

tao 0.35.3 的 `configurationForConnecting` 把配置对象在 UIKit 持有之前就释放了，iOS 27 上会在 `objc_retain` 崩溃。修法是在 vendored tao 里改成 `Retained::autorelease_ptr`。上游 0.36 有同样修法；没升级前保持这份补丁。

## 5. 平台代码怎么拆

指针、菜单、文件对话框、Vision OCR 留在 macOS。判断写在编译期，不写在运行时去调用再失败。

- 菜单和 `rfd` 只在 `target_os = "macos"`。`rfd` 即使关掉默认特性，非 macOS 的构建脚本仍会要求 GTK。
- OCR 同样只编进 macOS。
- 手机导入走书架上的文件选择，不走 Mac 的打开面板。
- 启动命令用 `ai_provider::build_command()`，不要写裸的 `Command::new("tool")`。这条是给仍要调外部程序的桌面路径。

交互不要用「是不是 iPhone」。Apple 的要求是看可用宽度：窄就用底栏和单列，宽就用 Mac 的侧栏。Lumi 现在以 719px 为界。桌面窗口缩到这个宽度时也会走窄屏，这是同一套规则，不是两套 App。

## 6. 交互：从指针改成手指

Apple 的尺寸：手指点击区域至少 44×44 pt。Mac 上 28 pt 的按钮到了手机上不够。悬停在触摸屏上不存在，所有「鼠标移上去才出现」的控件都要有一条不靠悬停的路径。

| Mac 上的动作 | 手机上应该变成 | 这次真实失败 |
| --- | --- | --- |
| 鼠标移到上沿，菜单出现 | 点页面中间叫出菜单，几秒后收回 | 手指坐标被读成 0，每次都被当成滑动，菜单出不来 |
| 点菜单项 | 手指抬起再执行，并吃掉随后那一次 click | 面板刚打开，同一次 click 落在遮罩上，立刻关掉 |
| 滚轮翻页 | 滚动模式跟着手指；仿真翻页跟着手指卷页 | 点页边会抢走滚动 |
| 悬停出删除 | 长按封面再出删除 | 删除钮常驻会挡住打开 |
| 右键、菜单栏、拖入文件 | 不做。导入用系统文件选择 | 这些 API 在手机上没有 |

安全区：返回、底栏和设置层要让开状态栏和 Home 指示条，用 `env(safe-area-inset-*)`。关键按钮不要只放在屏幕最顶上一行。

减少动效打开时，玻璃模糊应退回实色。这是系统开关，不是装饰。

## 7. 数据

- 手机书、进度、划线留在这个 App 的容器。卸载 App 会一起消失。7 天重签不应清容器；覆盖安装同一 bundle id 会保留。
- 不把 Mac 书库拷进手机，也不从手机写回 Mac。同步仍是 C7，排在 NAS 之后。
- 字体文件只留在这台设备。文案不要写「这台 Mac」。
- 不自动写整本书摘要。摘要页只列出已经点亮、可以按原句引用的书。

## 8. 开发顺序

每一项都先有失败测试，再改，再在真机上看。CSS 和文案可以不写测试，但真机要看。

1. 机器门：Xcode、目标、信任、签名。
2. 壳：场景清单、tao 补丁、`custom-protocol`、静态库、嵌入的是新 `dist`。
3. 打开一本本地书，能翻页，能回到书架。
4. 窄屏信息架构：底栏四页，桌面仍是左侧三栏。
5. 手指路径：菜单、设置、字体、划线、删除、滚动、仿真翻页。
6. 图标用 Mac 同一张，铺在不透明底上。iOS 图标不能靠透明通道。
7. 7 天后续签脚本只重复第 2 步的安装，不改数据。

不要在壳没过时改界面。一次只改一层，装上去用解压后的文案证明是新包。

## 9. 测试

先按「一次适配的套路」走完这一屏的状态名单，再勾下面的功能清单。状态名单里有未测项，这一版的视觉验收就未完成。2026-11-06 的几版只做了单元测试、解压核对和真机安装，没有模拟器运行时，所以那些状态都还是未测。

自动化，每次改交互都跑：

- `src/lib/pageTap.test.ts`：页边、正文、滑动、链接。
- `src/lib/pageCurl.test.ts`：短移动仍是点，长移动才卷页；滚动模式不卷页。
- `src/lib/menuChrome.test.ts`：手指抬起执行，并吃掉后续 click。
- `src/lib/readerDom.test.ts`：手指松开后下一帧才有选区。
- `src/lib/phoneTabs.test.ts`：四个标签和搜索。
- `pnpm exec tsc -b`。

真机，每装一版都看。模拟器没有这台手机的主屏幕和签名，不能代替。

1. 解锁，安装，启动。进程还在，屏幕不是黑的，没有本地网络报错。
2. 书架：四个标签能切换，玻璃底栏下面还能看见封面。
3. 导入一本小书。书出现在这台手机上。
4. 打开后，左上角「返回」回到书架。
5. 点页面中间，菜单出现。点「大小」，阅读设置留在屏幕上，能滚动，能改字号。
6. 仿真翻页：拨动时页面卷起，拨过约三分之一翻页，拨一点松开会回到原处。
7. 滚动：手指上下滑动文字跟着走，点页边不再抢走滚动。
8. 按住一段文字，出现划线。长按封面才出现删除。
9. 主屏幕图标是黑底绿猫头鹰。系统缓存旧图标时，重启手机再看。
10. Mac 上打开同一仓库的桌面版：侧栏还在，滚轮翻页还在，书库没有被手机改动。

记录时写：手机是否解锁、安装序号、二进制里解压到的那句文案。`BUILD SUCCEEDED` 和 `INSTALL:0` 只说明编过、装过，不说明里面是新界面。

## 10. 这次已经付过的学费

按出现顺序，避免再走一遍：

1. 旧 Xcode 签不了 iPhone 17。
2. 没有场景清单，启动即中断。
3. 写死场景代理类名，类还没注册就崩溃。
4. tao 0.35.3 提前释放场景配置，`objc_retain` 崩溃。
5. 没开 `custom-protocol`，手机去连 `localhost:5173`，黑屏。
6. release 脚本把上一份静态库又装了上去。删 fingerprint 再编。
7. Brotli 资源用明文搜索，误判成没嵌进界面。
8. 触点读成鼠标坐标 0，菜单和返回都点不到。
9. 菜单在 pointerdown 就打开，随后的 click 把设置层关掉。
10. 图标靠透明通道，主屏幕变成另一张图。要铺到不透明底上。
